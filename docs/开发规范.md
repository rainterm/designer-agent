# 开发规范

本规范面向 **designer-admin** 的二次开发与日常维护，覆盖后端（Solon + MyBatis-Plus）与前端（Vue 3 + Naive UI）。

**规范的优先级**：

1. **工具强制**——P3C / ESLint 报出的问题，先按工具规则改；
2. **本文档**——工具覆盖不到的架构约束、分层边界、安全要求；
3. **团队习惯**——前两者没有规定时，跟随同目录已有代码的写法。

> 只写工具查不出来的约定。能用静态检查固化的规则，不再用文档重复强调。

## 一、规范来源与检查

| 端 | 规范依据 | 工具 | 命令 |
|---|---|---|---|
| 后端 | 《阿里巴巴 Java 开发手册》 | P3C-PMD 2.1.1 + `maven-pmd-plugin` 3.21.0 | `mvn pmd:pmd` |
| 前端 | `@eslint/js` recommended + `eslint-plugin-vue` `flat/essential` | ESLint 10（扁平配置） | `pnpm run lint` / `pnpm run lint:fix` |

### 1.1 后端：阿里巴巴 Java 开发手册

规则集在根 `pom.xml` 的 `maven-pmd-plugin` 中声明，使用 P3C 的 10 组规则：

| 规则集 | 关注点 |
|---|---|
| `ali-naming.xml` | 类 / 方法 / 常量 / 包名命名，缩写词，POJO 后缀 |
| `ali-constant.xml` | 魔法值、常量定义与复用 |
| `ali-comment.xml` | 类注释、方法注释、作者与日期 |
| `ali-oop.xml` | 包装类比较、`equals`、`hashCode`、`BigDecimal` |
| `ali-concurrent.xml` | 线程池创建、`SimpleDateFormat`、并发集合 |
| `ali-exception.xml` | 异常捕获粒度、吞异常、`finally` 中使用 `return` |
| `ali-set.xml` | 集合初始化、`Arrays.asList`、遍历中删除 |
| `ali-flowcontrol.xml` | 嵌套深度、条件赋值、`switch` 默认分支 |
| `ali-orm.xml` | `SELECT *`、`count` 写法、批量操作 |
| `ali-other.xml` | 日志占位符、`System.out`、注释与文件编码 |

使用方式：

```bash
# 全量扫描（每个模块各生成一份报告）
mvn pmd:pmd

# 需要 HTML 报告
mvn pmd:pmd -Dformat=html
```

- 报告默认输出到各模块的 `target/pmd.xml`（`-Dformat=html` 时为 `target/pmd.html`）。
- **当前 `failOnViolation=false`**：扫描只暴露问题、不阻断构建。这并不意味着可以忽略——PMD 优先级 **1 / 2**（High）的问题必须在评审前修掉，优先级 3 至少要在 PR 里说明原因。
- **`typeResolution=false` 是刻意的**：PMD 6.55 的 ASM 读不了 JDK 25 的编译产物，开启类型解析会直接报错；P3C 的规则主要基于语法树，关掉后仍能覆盖绝大多数条目。因此「报告 0 违规」只代表语法树层面干净，不代表完全符合手册。
- 工具的 `targetJdk` 仍写 `20`（P3C 规则的解析上限），与实际编译的 `release 25` 无关，不要据此改编译版本。

### 1.2 前端：ESLint

配置入口 `designer-ui/admin-web/eslint.config.js`（扁平配置），由三部分组成：

| 来源 | 作用 |
|---|---|
| `js.configs.recommended` | JS 正确性规则（未定义变量、不可达代码等） |
| `pluginVue.configs['flat/essential']` | Vue 3 正确性规则（模板语法、`v-for` key 等） |
| 项目自定义规则 | 见下表 |

**为什么用 `flat/essential` 而不是 `flat/recommended`**：`recommended` 含 `vue/html-indent`、`vue/max-attributes-per-line` 等上百条纯格式规则，等于用 ESLint 再造一个格式化器。本项目**不接 Prettier**，缩进、引号、分号、换行由编写者决定，工具只负责抓真实缺陷。

项目自定义规则：

| 规则 | 级别 | 说明 |
|---|---|---|
| `eqeqeq: ['error', 'smart']` | error | 强制 `===`，但允许 `x == null`（同时判 `null` 与 `undefined`） |
| `prefer-const` | error | 不再重新赋值的 `let` 必须改 `const` |
| `no-var` | error | 禁止 `var` |
| `no-unused-vars` | error | 下划线开头的参数 / 变量视为刻意保留；`catch (e)` 不强制引用 |
| `no-console` | warn | 只允许 `console.warn` / `console.error` |
| `vue/no-unused-refs` | error | 声明了 `ref` 却没用，通常是漏绑 |
| `vue/component-api-style` | error | 只允许 `<script setup>` |
| `vue/multi-word-component-names` | off | 项目大量 `index.vue` / `403.vue` 这类视图 |

其他约定：

- 忽略 `dist/**`、`node_modules/**`、`public/**`。
- `main.js` 单独放行 `vue/no-reserved-component-names`：全局注册的 `Dialog` 与原生 `<dialog>` 同名，但模板中 PascalCase 不会解析成原生标签。
- `vite.config.js` 与 `plugins/**` 使用 Node 全局变量，与浏览器代码分开配置。

```bash
cd designer-ui/admin-web
pnpm run lint        # 检查
pnpm run lint:fix    # 自动修复可修复项
```

## 二、工程结构与依赖方向

### 2.1 后端模块

| 模块 | 直接依赖 | 职责 |
|---|---|---|
| `designer-common` | 无（仅第三方库） | `Result` / `PageQuery` / `PageResult` / `BaseEntity` / `BizException` / 注解 / 工具 |
| `designer-framework` | `designer-common` | 鉴权、限流、验证码、操作日志、任务、存储、消息、MyBatis 增强等技术能力与 SPI 定义 |
| `system-api` | `designer-common` | 系统模块对外契约 |
| `system-service` | `system-api`、`designer-framework` | RBAC、认证、文件、消息、任务、监控实现 |
| `demo-api` / `demo-service` | 见下 | 二次开发模板模块 |
| `agent-api` / `agent-service` | `designer-common` / `designer-framework` + Solon AI | 智能体（供应商 / 工具 / MCP / Skill / 工作流 / 知识库 / 会话） |
| `module-*-api` | `designer-common` | 业务模块对外契约 |
| `module-*-service` | `module-*-api`、`designer-framework` | 业务实现；需要系统能力时依赖 `system-api` |
| `designer-server` | 各 `*-service` | 唯一启动组装模块（单进程） |

**硬约束**：

- `framework` **不得**依赖 `system`。跨层能力由 `framework` 定义接口（`PermissionLoader`、`OperLogWriter`、`MessageBus`、`JobLogWriter` 等），由 `system-service` 提供实现。
- 跨模块只依赖对方 **`*-api`**，不依赖 `*-service`。
- `*-api` 只放按需的 `*Api` 及其入参 / 出参类型；entity / dto / vo 与内部 `*Service` 留在 `*-service`。
- `*-service` 在同名 `api` 包实现 `*ApiImpl`，由它完成 Api 类型 ↔ 内部 model 的转换。
- `designer-server` 只依赖各 `*-service`，不放业务代码。

**判断依赖是否合理**：如果 `framework` 里出现了 `com.designer.admin.system.*` 的 import，就是依赖方向被破坏了。

### 2.2 前端分层

```
src/
├── layout/          # 布局壳（侧栏 / 顶栏 / 页签 / 消息中心 / 偏好设置）
├── views/           # 壳层页面（login / dashboard / error）
├── router/          # 常量路由 + 动态路由注册
├── store/           # Pinia：user / app / setting / notice
├── api/             # 壳层接口：request / auth / captcha / monitor
├── modules/         # 业务模块，按模块隔离
│   └── <module>/
│       ├── api/     # 该模块接口
│       └── views/   # 该模块页面，按业务域分子目录
├── components/      # 全局通用组件
├── composables/     # 可复用组合式函数
├── constants/       # 常量
├── directives/      # 全局指令（v-perm）
├── theme/           # 主题色派生与 Naive UI overrides
├── styles/          # 全局样式与 CSS 变量
└── utils/           # 工具函数
```

- 依赖只能自上而下：**业务模块 → 公共层**，公共层不得反向依赖 `modules/` 或 `views/`。
- **模块之间不互相 import**：跨模块数据走后端接口；确实通用的能力提升到 `components/` / `composables/`。
- 业务代码一律放进 `modules/<module>/`，不要往壳层的 `views/` / `api/` 里塞。

## 三、接口约定

### 3.1 接口前缀

按「访问方 + 鉴权方式」划分，路由与拦截规则都据此判断：

| 前缀 | 面向 | 鉴权 | 响应体 |
|---|---|---|---|
| `/admin-api/**` | 管理后台 | Sa-Token 登录态，token 放 `Authorization` 头（不带 `Bearer`） | `Result` |
| `/app-api/**` | 前台 / 移动端公开接口 | 默认免登录，由业务自行控制 | `Result` |
| `/open-api/**` | 第三方开放接口 | OAuth2 `access_token` + 按路径匹配 Scope | `Result`；令牌端点返回 RFC 6749 JSON |

- `/open-api/oauth2/**` 是令牌端点，只校验 `client_id` / `client_secret`。
- 后端 8080 只绑定回环地址，外部流量统一经 Nginx 的 `/admin-api`、`/app-api`、`/open-api` 前缀转发。
- SSO 相关接口见 [SSO 接入](SSO.md)。

### 3.2 统一响应

```java
public class Result<T> {
    private int code;
    private String msg;
    private T data;
}
```

- 成功：`Result.ok()` 或 `Result.ok(data)`。
- 失败：抛 `BizException`，由 `GlobalExceptionFilter` 转成 `Result.fail(code, msg)`。
- 状态码常量统一取 `ResultCode`（`200 / 400 / 401 / 403 / 404 / 429 / 500`），不要在业务里写数字。
- **未知异常不回传原始信息**：`GlobalExceptionFilter` 只记录日志，响应统一「系统繁忙，请稍后重试」，避免泄露 SQL、类名与路径。
- 非 `Result` 结构的接口（文件流、OAuth2 令牌端点、智能体 SSE 流式对话 / 工作流试跑 / 文档重建索引）需在文档中显式说明（`@ApiOperation` 注明「SSE，非 Result 包装」）。
- 新增管理端业务 Controller 后，必须在 `DocConfig#docDocketAdmin` 增加对应包扫描，否则 `doc.html` 看不到接口。

### 3.3 分页

- 查询 DTO 继承 `PageQuery`，直接获得 `pageNum` / `pageSize` 与 `toPage()`。
- `PageQuery` 已做兜底：页码小于 1 归一到 1，`pageSize` 最大 500。
- 返回用 `PageResult.of(IPage)`，字段固定为 `total / pageNum / pageSize / records`。

### 3.4 接口文档

- Controller 标注 `@Api(tags = "...")`，方法标注 `@ApiOperation(value = "...")`；只有同时标注两者的接口才会出现在 `doc.html`。
- 入参 DTO / VO 字段用 `@ApiModelProperty` 说明含义与是否必填。
- 新增 Controller 所在包若不在 `DocConfig` 的扫描范围内，需同步补充分组，否则文档里看不到。

## 四、后端规范

### 4.1 分层职责

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller | 参数接收、校验注解、权限注解、限流 / 操作日志注解、调用 Service、包装 `Result` | 写业务逻辑、直接操作 Mapper |
| Service | 业务规则、事务、缓存、组装 DTO / VO、跨 Mapper 编排 | 处理 HTTP 上下文（除明确需要 `Context` 的登录 / 下载） |
| Mapper | 数据访问；单表用 Wrapper，连表用 mpj 的 `default` 方法 | 出现 `@Select` / `@Update` 等注解 SQL，或业务判断 |
| Entity | 对应表结构，继承 `BaseEntity` | 承载业务逻辑、直接作为接口出参（除少量内部接口） |
| DTO / VO | 入参 / 出参 | 与 Entity 混用 |

### 4.2 命名

**《开发手册》强制项**：

| 类型 | 规则 | 示例 |
|---|---|---|
| 类 | UpperCamelCase | `SysUserServiceImpl`、`AutoDataScopeHandler` |
| 方法 / 参数 / 变量 | lowerCamelCase | `listRouters`、`deptId` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_TTL_SECONDS`、`MAX_TEXT` |
| 包名 | 全小写，点分隔 | `com.designer.admin.system.service.rbac` |
| 抽象类 | `Abstract` 或 `Base` 前缀 | `AbstractQuartzJob`、`BaseEntity` |
| 异常类 | `Exception` 结尾 | `BizException`、`RateLimitException` |
| 测试类 | `Test` 结尾 | `SysUserServiceTest` |
| POJO 布尔字段 | 不加 `is` 前缀 | 用 `status`（1/0）而非 `isEnabled` |

**本项目细则**：

- 系统域统一 `Sys` 前缀（`SysUserController`、`SysRoleMapper`、`SysDept`）；跨模块通用能力不加（`AuthController`、`ProfileController`、`HealthController`）。
- 业务模块包名 `com.designer.admin.module.<name>`，权限标识 `<name>:<resource>:<action>`。
- 实体不加 `Entity` 后缀；DTO / VO 分别以 `DTO` / `VO` 结尾；查询对象以 `QueryDTO` 结尾。
- 常量类按域收敛（`SystemConsts`、`SystemCacheConsts`、`RedisKeyConsts`），不要在各处定义局部常量。
- 缩写词按普通单词处理：`deptId` 而不是 `deptID`，`oauthClient` 而不是 `oAuthClient`。

### 4.3 注释

- 所有类、公共方法写 Javadoc，至少说明**为什么这样做**，而不只是复述方法名。
- 复杂分支、非直观的 SQL / 缓存键、绕过某条规则的地方，必须写明原因。
- 修改代码时同步更新注释；**过时的注释比没有注释更有害**。
- 不保留被注释掉的死代码，历史交给 Git。

### 4.4 参数校验

- Controller 类标注 `@Valid`；**所有 `@Body` 参数必须再加 `@Validated`**，否则 DTO 字段上的约束不会生效：

  ```java
  public Result<Void> add(@Body @Validated UserSaveDTO dto) { ... }   // ✅ 字段约束生效
  public Result<Void> add(@Body UserSaveDTO dto) { ... }              // ❌ 字段约束被忽略
  ```

- 约束注解选择：

  | 场景 | 注解 |
  |---|---|
  | 必填字符串 | `@NotBlank` |
  | 必填对象 / 数字 | `@NotNull` |
  | 长度范围 | `@Length(min, max)` |
  | 格式（手机号、密码强度） | `@Pattern` |
  | 数值范围 | `@Min` / `@Max` |

- `@Length` / `@Pattern` 遇到空值直接放行，空值语义交给 `@NotBlank` / `@NotNull`；**允许留空的字段不要加 `@NotBlank`**（例如存储配置的 `urlPrefix`，留空表示沿用默认值）。
- 服务层仍需兜底：Excel 导入等绕过 DTO 的入口不会被 DTO 校验覆盖。
- 校验失败的响应由 `GlobalExceptionFilter` 统一转换，不要在 Controller 里手写 `if (x == null) return Result.fail(...)`。

### 4.5 事务

- 写操作在 Service 实现层使用 `@Transaction`，事务边界紧贴数据库写操作，避免长事务。
- 事务方法内**不要**做远程调用、文件读写、消息发送等耗时操作；需要时放到事务提交之后。
- **自调用不生效**：`this.foo()` 不会经过代理，`@Transaction` / `@Cache` / `@RateLimit` 都会失效。需要横切能力时把方法放到另一个 bean，或从外部入口调用。
- 只有 `RuntimeException` 会触发回滚；受检异常需要显式处理或包装成 `BizException`。
- 事务与缓存失效的顺序：**先写库，再在 `afterCommit` 里删缓存**（参考 `PermissionInvalidator` 的实现）。

### 4.6 缓存

- 使用 Solon 的 `@Cache` / `@CacheRemove`，底层由 `RedisCacheService` 落到 Redis，多实例共享。
- **只缓存「读多写少 + 与调用者无关」的公共数据**：字典、下拉选项、启用的 Scope / 白名单、系统设置公开信息。带分页或关键字的查询不加。
- 读侧 `@Cache` 与写侧 `@CacheRemove` 必须成对出现；新增写入口时，回头检查会影响哪些已缓存的读接口。
- 键名与 tag 统一写在 `SystemCacheConsts`，注解里不写裸字符串。
- `key = "...:#{dictType}"` 的变量名必须与方法参数名一致（依赖根 pom 已开启的 `-parameters`）。
- 失效优先「按 tag 整体清」，而不是逐个精准删 key；这类数据量小、维度有限，全清更不容易漏。
- 缓存是旁路：`RedisCacheService` 读写失败时 fail-open，只记日志，让业务回源数据库。

### 4.7 数据访问

- 所有 Mapper 继承 `MPJBaseMapper<T>`。
- 单表查询优先 `LambdaQueryWrapper`，用方法引用而不是字符串列名。
- 连表查询用 mpj 链式 API，优先写在 Mapper 的 `default` 方法里。
- Mapper 中不出现 `@Select` / `@Update` 等注解 SQL。
- 动态条件用 `eq(condition, ...)` 形式，不要手工拼 SQL 字符串。
- 批量操作使用 MyBatis-Plus 的批量方法；避免在循环里逐条查库（N+1）。

### 4.8 数据权限

- 配置在角色上（`sys_role.data_scope`），多角色取并集，超管不受限。
- 过滤由 `AutoDataScopeHandler` + `LazyHandlerDataPermissionInterceptor` 在 SQL 层完成，**业务代码不写 `dept_id IN (...)`**。
- 归属列默认取 `create_by`（由 `AutoFillHandler` 自动填充）；有 `dept_id` 用 `dept_id`，没有则反查 `sys_user` 的部门。
- 需要「数据归属创建时部门」的业务（合同、凭证等），必须给表加 `dept_id`。
- 写入前的越权校验走 `DataPermissionGuard#canSeeDept`，不能用查询过滤替代。
- 必须绕开时用 `DataPermissionContext.ignore(...)` 或 `@InterceptorIgnore(dataPermission = "true")`，并写明原因。
- 新增框架级共享表沿用 `sys_` 前缀即可自动排除创建人维度；`sys_role_dept` 必须始终忽略。

### 4.9 权限缓存失效

写 `sys_user_role` / `sys_role` / `sys_role_menu` / `sys_menu` 的入口，必须调用 `PermissionInvalidator`：

| 变更 | 调用 |
|---|---|
| 用户 ↔ 角色关系 | `evictUser` / `evictUsers` |
| 角色本身（标识、状态、菜单分配） | `evictRole` / `evictRoles` |
| 菜单（perms、状态、删除） | `evictMenu` / `evictMenus` |
| 部门树结构变化 | `evictAllUsers` |

优先复用现有 Service 方法，不要让写操作绕过它们。漏调用的后果是：鉴权继续使用旧快照，直到 TTL 到期，属于越权而非「缓存陈旧」。

### 4.10 日志

- 使用 Lombok `@Slf4j`，日志参数用占位符：`log.info("注册消息通道 Provider：{} ({})", type, label)`。
- **禁止** `System.out.println` / `e.printStackTrace()`（P3C 同样会报）。
- 异常日志必须带上下文（关键 ID、路径），并传异常对象：`log.error("任务执行异常 jobId={}", jobId, e)`。
- 级别选择：`error` 只给需要人工介入的故障；业务校验失败用 `warn` 或直接抛 `BizException`；高频路径（如限流命中）用 `debug`，避免刷日志。
- 敏感信息（密码、token、密钥）不落日志。
- 操作日志用 `@OperLog`，由拦截器统一记录；涉及密码等敏感参数时设 `saveParam = false`。

### 4.11 异常

- 业务失败抛 `BizException`，由全局过滤器统一转成 `Result`；不要用返回值表达失败。
- **不要吞异常**：`catch` 后要么处理、要么带上下文重新抛出；`catch (Exception ignored)` 只允许出现在「旁路能力失败不影响主流程」的场景，并写明原因。
- 不使用异常控制正常流程。
- `finally` 中不写 `return`。
- 捕获尽量具体，避免直接 `catch (Throwable)`；框架层的兜底除外。

### 4.12 常量与魔法值

- 不允许魔法值直接出现在代码里（P3C `ali-constant`）：状态、类型、超时、路径前缀、缓存键都要有常量或配置项。
- 状态值用常量类表达（`SystemConsts.STATUS_ENABLE`），不要散落 `1` / `0`。
- 可变配置放 `app.yml` 或数据库配置，不要为了「灵活」堆一串常量。

### 4.13 集合、空值与并发

**《开发手册》相关强制项**：

- 包装类型比较用 `equals`，不要用 `==`；`BigDecimal` 比较用 `compareTo`。
- 判断集合为空用 `CollectionUtils.isEmpty()` / `isEmpty()`，不要 `size() == 0`。
- `Arrays.asList` 返回定长列表，不能再 `add` / `remove`。
- 不在 `foreach` 循环中 `add` / `remove` 集合元素，用 `Iterator` 或 `removeIf`。
- 初始化集合时指定容量（可预估大小时）。
- **线程池不允许用 `Executors` 创建**，必须显式 `ThreadPoolExecutor` 并指定队列与拒绝策略。
- `SimpleDateFormat` 线程不安全，用 `DateTimeFormatter`。

**本项目约定**：

- 旁路任务统一 `RunUtil.asyncAndTry(...)`，异常被吞掉并记录；不要自建线程。
- 项目已开启虚拟线程（`solon.threads.virtual.enabled`），I/O 密集型任务无需再手写线程池。
- 需要独立执行器时（批量计算、报表导出），单独定义并配置队列与拒绝策略，不要挤占 Web / 调度线程。

### 4.14 安全

- 不信任任何外部输入：路径、文件名、排序字段、跳转地址都要白名单或正则校验。
- 文件上传按扩展名白名单推导 Content-Type，不采信客户端声明。
- 密码用 BCrypt 哈希；日志、接口响应、导出文件都不出现密码与哈希。
- 敏感字段用 `@Sensitive` 序列化脱敏（手机号、邮箱、密码）。
- 存储 AccessKey、SMTP 密码等配置用 `VAULT_PASSWORD` 加密后落库，密钥只通过环境变量注入。
- 新增公开接口（`/app-api/**`）必须评估是否需要限流与防刷。

### 4.15 后端禁止清单

- ❌ `framework` 依赖 `system`
- ❌ 业务模块依赖其他模块的 `*-service`
- ❌ Mapper 写注解 SQL
- ❌ Controller 写业务逻辑
- ❌ `@Body` 参数漏 `@Validated`
- ❌ 在 Service 内部 `this.xxx()` 调用带事务 / 缓存 / 限流注解的方法
- ❌ 写权限相关表后不失效权限快照
- ❌ 业务代码手写 `dept_id IN (...)`
- ❌ 魔法值、裸字符串缓存键
- ❌ `System.out` / `printStackTrace` / 吞异常
- ❌ 把 `Entity` 直接当接口出参暴露敏感字段

## 五、前端规范

技术栈：Vue 3（组合式 API、`<script setup>`）+ Naive UI + Vite + Pinia，路径别名 `@` → `src`。

### 5.1 目录与模块组织

- 业务代码放 `modules/<module>/`，模块内可自建 `components/`、`utils/`（参考 `modules/demo`）。
- 页面按业务域分子目录：`modules/system/views/user/index.vue`。
- 通用组件放 `components/`，跨模块通用的可在 `main.js` 全局注册（`PageTable`、`SearchBar`、`Dialog`、`DetailDrawer` 等）。
- 可复用逻辑抽到 `composables/useXxx.js`，不复制粘贴。

### 5.2 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| `.vue` 组件文件 | PascalCase | `PageTable.vue`、`AttachmentUploader.vue` |
| `.js` 文件 | camelCase | `pageLoading.js`、`noticeLink.js` |
| 组合式函数 | `useXxx.js`，导出 `useXxx()` | `usePagination.js` |
| 常量 | UPPER_SNAKE_CASE | `LAYOUT_MODES`、`DEFAULT_PRIMARY` |
| 样式类名 / CSS 变量 | kebab-case | `.page-container`、`--color-primary` |
| 接口函数 | `pageXxx` / `getXxx` / `createXxx` / `updateXxx` / `deleteXxx` | `pageUsers`、`updateUser` |
| Store | `useXxxStore`，文件 `store/xxx.js` | `useUserStore` |

### 5.3 ESLint 与写法

按 1.2 的规则执行，重点注意：

- **`eqeqeq: smart`**：只允许 `x == null` 这种同时判断 `null` / `undefined` 的写法，其余一律 `===`。
- **`prefer-const`**：声明后不再赋值就用 `const`。
- **`no-unused-vars`**：下划线前缀表示刻意保留（如 `const { pageNum: _n, ...rest } = query`）；`catch (e) {}` 允许不引用异常对象。
- **`no-console`**：只保留 `console.warn` / `console.error`，调试用的 `console.log` 不要提交。
- **`vue/component-api-style: script-setup`**：不写 Options API，不写 `defineComponent`。
- **`vue/no-unused-refs`**：模板 `ref="xxx"` 与 `const xxx = ref()` 必须对应。
- 缩进 / 引号 / 分号不做强制，但**同一文件内保持一致**；新建文件跟随仓库主流风格（2 空格、单引号、无分号）。

### 5.4 组件

```vue
<script setup>
import { computed, ref } from 'vue'

const props = defineProps({
  /** 标题 */
  title: { type: String, default: '' }
})
const emit = defineEmits(['confirm'])

const visible = ref(false)
const text = computed(() => props.title || '未命名')
</script>
```

- 一律 `<script setup>`；需要手工透传 `$attrs` 时用 `defineOptions({ inheritAttrs: false })`。
- `props` 必须声明类型与默认值，复杂对象用工厂函数。
- 事件用 `defineEmits` 显式声明，命名 `update:xxx` 或动词短语。
- 组件只负责展示与交互，接口调用与业务状态放在页面或 composable。
- 不写 `v-html`（降低 XSS 面）；确需富文本时先做白名单清洗。

### 5.5 组合式函数与列表页

列表页优先拼装，不重复造轮子：

```vue
<SearchBar :pager="pager">
  <template #fields>
    <n-form-item label="账号">
      <n-input v-model:value="pager.query.username" />
    </n-form-item>
  </template>
</SearchBar>

<PageTable :pager="pager" :columns="columns" />
```

| 能力 | 用法 |
|---|---|
| `usePagination(fetcher)` | 查询条件、分页、加载态、勾选、排序、重置；返回值直接给 `SearchBar` / `PageTable` |
| `useFormDialog()` | 新增 / 编辑弹框状态机，校验通过后自动关闭 |
| `useBatchDelete()` | 批量删除 + 二次确认 |
| `useConfirmAction()` / `useActionLock()` | 危险操作确认、按钮防重复点击 |
| `useDict()` | 字典加载与缓存 |
| `useClientSort()` | 前端排序 |

约定：

- `fetcher` 返回 `{ records, total }` 或 axios 风格 `{ data: { records, total } }`，由 `usePagination` 统一归一化。
- 查询参数中的空字符串 / `null` / `undefined` 默认会被清理，不需要手写过滤。
- 导出等「取当前筛选条件」的场景用 `pager.getFilters()`，不要手工摘掉 `pageNum`。

### 5.6 接口请求

- 统一走 `@/api/request`：
  - `baseURL` 取 `VITE_API_BASE`（默认空，走同源 / 代理）；
  - `Authorization` 直接放 token 原值，**不带 `Bearer`**；
  - `FormData` 自动去掉 `Content-Type`，由浏览器生成 boundary；
  - 后端返回 `{ code, msg, data }`：`200` 成功；`401` 清 token 并跳登录；其余弹 `message.error` 并 reject；非统一结构（文件流）原样返回。

- 普通 REST 走 `@/api/request`；**SSE 流式接口**可用原生 `fetch`（EventSource / ReadableStream），在模块 `api` 内单独封装并注明鉴权头。
- 接口按模块放在 `modules/<module>/api/`，一个文件按业务域用注释分组：

  ```js
  import request from '@/api/request'

  // ---------------------- 用户 ----------------------
  export const pageUsers = (params) => request.get('/admin-api/system/user/page', { params })
  export const createUser = (data) => request.post('/admin-api/system/user/add', data)
  export const deleteUsers = (ids) =>
    request.delete('/admin-api/system/user/remove', { params: { ids: ids.join(',') } })
  ```

- 后台轮询类请求（如菜单红点）加 `{ silent: true }`，失败不弹提示。
- 不要在前端拼接 `baseURL` 或硬编码域名，统一走相对路径。

### 5.7 路由与权限

- 常量路由写在 `router/index.js` 的 `constantRoutes`；登录后按后端菜单树动态注册。
- 菜单 `component` 字符串解析约定：`{module}/{path}` → `src/modules/{module}/views/{path}.vue`（如 `system/user/index`、`demo/index`）；`Layout` 表示目录分组。
- 视图通过 `import.meta.glob('../modules/*/views/**/*.vue')` 自动收集，新增页面不需要改路由文件。
- 隐藏页（编辑 / 详情等）对应菜单 `visible=0`：注册路由但不进侧栏。
- 按钮级权限用 `v-perm`，无权限时元素直接移除：

  ```html
  <n-button v-perm="'system:user:add'">新增</n-button>
  ```

- 需要代码里判断权限时用 `userStore.hasPerm('system:user:add')`，不要自己解析权限字符串。

### 5.8 状态管理

- 使用 Pinia，文件 `store/<name>.js`，`defineStore('<name>', ...)`。
- 需要持久化的状态自行读写 `localStorage`（参考 `store/app.js` 的 `persist()`），不要引入额外持久化插件。
- `store/user.js` 持有 token、用户信息、角色 / 权限、动态路由与加载标记。
- `store/setting.js` 持有系统名称 / Logo / 默认布局与主题色；`store/notice.js` 负责站内信 SSE 与未读数。
- 组件内不直接读写 `localStorage`，统一走 store 或 `utils/auth.js`。

### 5.9 样式与主题

- 颜色、圆角、间距一律用 CSS 变量（`--color-primary`、`--color-surface`、`--color-border`、`--radius`）或 Naive UI 的 `themeOverrides`，不写死色值。
- 主色由 `theme/index.js` 的 `buildColors()` 派生完整色板；新增主题维度时在这里扩展，不要在页面里算颜色。
- 业务页统一用 `.page-container` 包裹，卡片使用项目约定的边框与圆角（无阴影）。
- 弹框、表格、搜索区优先用公共组件，页面内不重复写样式。
- 改主题 / 布局后确认偏好设置持久化与「系统设置」默认值回退都正常。

### 5.10 前端禁止清单

- ❌ 业务代码放到 `views/` 或 `api/` 壳层
- ❌ 模块之间互相 `import`
- ❌ `<script setup>` 之外再写 Options API
- ❌ 直接用 `axios` 发请求、绕过 `@/api/request`
- ❌ 硬编码色值 / 圆角 / 域名
- ❌ `v-html` 渲染不可信内容
- ❌ 提交 `console.log`、调试代码、注释掉的整段逻辑
- ❌ 复制粘贴列表页逻辑而不复用 `usePagination` / `PageTable`

## 六、数据库与 SQL

### 6.1 表与字段

- 表名、字段名小写下划线：`sys_user`、`create_time`、`data_scope`。
- 主键统一 `id BIGINT` 自增；实体继承 `BaseEntity` 时不要再重复声明 `id`。
- 业务表标准审计列：`create_by`（用户名）、`create_time`、`update_by`、`update_time`、`deleted`。
  - 这几个字段由 `AutoFillHandler` 自动填充，业务代码不要手写。
  - `deleted` 由 `@TableLogic` 生效，查询自动追加 `deleted = 0`。
- **关联表与流水表不继承 `BaseEntity`**：前者随主表整批重写，后者按保留期物理清理，软删只会让数据无限堆积。
- 需要参与数据权限的表保留 `create_by`；需要「数据归属创建时部门」的再加 `dept_id`。
- 框架级共享表沿用 `sys_` 前缀（自动跳过创建人维度）。

### 6.2 索引与约束

- 唯一索引 `uk_<字段>`，普通索引 `idx_<字段>`。
- 唯一性优先由数据库保证，Service 层的重复校验只用于给出友好提示。
- 逻辑删除表的唯一索引需要把 `deleted` 纳入考虑，避免删除后无法重建同名数据。

### 6.3 SQL 编写

**《开发手册》相关强制项**：

- 不使用 `SELECT *`，明确列出需要的列。
- 统计行数用 `count(*)`，不要用 `count(列名)` / `count(1)` 替代。
- 批量操作控制单次数量（建议 500 以内），避免超长 SQL。
- 禁止大事务与循环内查询。

**本项目约定**：

- 单表查询用 `LambdaQueryWrapper`，SQL 由 MyBatis-Plus 生成；不要为了「可读」而手写 XML。
- 连表查询写在 Mapper 的 `default` 方法里，用 mpj 链式 API。
- 分页统一 `selectPage(query.toPage(), wrapper)`，不要自己拼 `LIMIT`。
- 数据权限的过滤条件由拦截器追加，业务 SQL 不要重复写部门条件。

### 6.4 脚本管理

- **初始化脚本**：`sql/init/mysql/`，按模块分目录（`_base` / `system` / `demo` / `agent` …），由 `00-run-init.sh` 顺序导入（当前 `MODULES=(system demo agent)`）。
  - 脚本是**破坏性**的（`DROP TABLE` 重建 + 种子数据），只用于首次初始化或本地重置。
  - 新增模块时增加同名目录，并把模块名加入脚本的 `MODULES`。
  - 默认库名占位符为 `designer_agent`（与 `app.yml` 的 `DB_NAME` 默认值一致），执行时按环境变量替换。
- **版本要求**：`schema.sql` 用函数索引 `(IF(deleted = 0, 0, NULL))` 在逻辑删除下维持唯一约束，依赖 **MySQL 8.0.13+**；更低版本或 MariaDB 需改为虚拟生成列 + 普通唯一索引。
- **智能体相关配置**（`app.yml`）：
  - `designer.agent.workspace`：Solon AI Harness 工作区（默认 `./data/agent-harness`）
  - `designer.agent.milvus.*`：知识库向量库（本地可用 `./deploy/deploy-milvus.sh`）
- **增量升级**：约定放在 `sql/upgrade/mysql/`，命名 `V{版本}__{说明}.sql`，版本单调递增，只追加不修改历史脚本。
  - 生产变更要求：先备份、再执行、可回滚，并在发布记录中登记版本。
  - 当前未接入 Flyway / Liquibase，升级需人工评审与执行；后续接入时以现有 `schema.sql` 为 baseline。

## 七、新增业务模块

以后端新增业务 `foo` 为例，**不要修改** `common` / `framework` / `system`。模板是 `designer-module-demo` 与前端 `src/modules/demo`；完整业务参考 `designer-module-agent` 与 `src/modules/agent`。

### 7.1 接入步骤

1. **后端**：复制 `designer-module-demo` → `designer-module-foo`（含 `foo-api` / `foo-service`），改 `artifactId`、`name` 与包名。
2. 根 `pom.xml`：
   - `<modules>` 增加 `designer-module-foo`；
   - `<dependencyManagement>` 增加 `foo-api` / `foo-service`。
3. `designer-server/pom.xml` 增加对 `foo-service` 的依赖（只依赖 `*-service`）。
4. **`DocConfig`**：管理端 Controller 包加入 `docDocketAdmin.apis(...)`。
5. **前端**：复制 `designer-ui/admin-web/src/modules/demo` → `src/modules/foo`，改接口前缀与视图。
6. **SQL**：在 `sql/init/mysql/foo/` 增加 `schema.sql` / `data.sql`（继承 `BaseEntity` 的表必须含 `deleted`），并把 `foo` 加入 `00-run-init.sh` 的 `MODULES`。
7. **菜单**：在「系统管理 → 菜单管理」新增菜单，`component` 填 `foo/index`，按钮权限填 `foo:xxx:yyy`（或写入模块 `data.sql`）。
8. 重新打包：`mvn -pl designer-server -am package`，前端 `pnpm run build`。

菜单 `component` 与文件的对应关系：

| 菜单 component | 实际文件 |
|---|---|
| `foo/index` | `modules/foo/views/index.vue` |
| `foo/order/index` | `modules/foo/views/order/index.vue` |
| `agent/agent/index` | `modules/agent/views/agent/index.vue` |
| `Layout` | 目录分组，不对应文件 |

### 7.2 跨模块调用

1. 在 `*-api` 的 `...api` 包中按需新增 `XxxApi` 接口。
2. `XxxApi` 的入参 / 出参类型在 `*-api` 内自行定义，**不要复用** service 侧的 entity / dto / vo。
3. 在 `*-service` 的同名 `...api` 包实现 `XxxApiImpl`，由它完成 Api 类型 ↔ 内部 model 的转换。
4. 其他模块只依赖 `xxx-api`，用 `@Inject XxxApi` 注入。

参考实现：`designer-module-demo` 的 `DemoApi` / `DemoApiImpl`。
